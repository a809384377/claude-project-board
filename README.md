# project-board · 项目状态看板

一个 Claude Code 插件（也能在 [pi](#在-pi-里使用) 里用）：在终端里给你的项目放一块**跟着项目走、跨会话不丢的状态看板**。

做一个稍大的项目时，常见的烦恼是：Claude 每次新开会话都不记得上次做到哪、你拍过什么板、有哪些约定。project-board 把这些记在项目里的一个文件（`ai/board.json`）里：目标、步骤、事项、你做过的决策、项目约定、资料。Claude 开工前自动读到它，干完活随手更新它；你在终端里一眼看到「现在关注什么、谁在跑、什么等你过目」，并可以直接点按钮同意提议、打开要看的文件或链接。

## 安装

在 Claude Code 的输入框里输入这一行（需要联网访问 GitHub）：

```
/plugin install project-board --marketplace a809384377/claude-project-board
```

之后按提示操作：先输入 `y` 同意添加这个插件市场，再选作用域，建议选 **user**（对你所有项目生效；看板本身只在含 `ai/board.json` 的项目里才显示）。如果插件有设置项，会接着出现设置界面，保持默认即可。装好后当前会话立即生效，无需重启。

## 在项目里启用

只有含 `ai/board.json` 的项目才会显示看板、向 Claude 注入看板内容；其他项目里插件只响应 `/board init`，不会打扰你。

```
/board init              在当前项目根创建空看板，项目名取目录名
/board init 类型          同上，并把项目类型记下来（可选，自由填写，如 miniapp）
```

也可以直接对 Claude 说「给这个项目建一个看板」，它会调用 `board_init`。创建后，完整的看板工具从 Claude 的下一轮对话起可用。

## 看板怎么看

结构是三层：**目标 → 步骤 → 事项**。

- **目标**：你确认过的一件完整的事，带一句「做到什么算完」。
- **步骤**：为达成目标而分的阶段（如 A→B→C→D）。步骤条形如 `✓ T › ◐ A 22/23 › ◆ B 12/17`；点步骤可展开或收起它的事项，有事项在跑、待你看或在做的步骤自动展开，你点过的开合会被记住。没有事项的步骤不占一行。只有几件事的目标可以不拆步骤。
- **事项**：具体要做的一件事，一事项一行：标题（过长截断），行尾是简短标签（负责人 `@main`、`等：…`、别的会话报告的时间）。依赖、备注、完整的等待说明、验收标准点开事项才显示。状态有：待办 `○`、排队 `⏸`、在做 `◐`、在跑 `●`、待你看 `◆`、已看 `◇`、完成 `✓`、搁置 `⊘`。别的会话报告「在跑」的事项，超过 12 小时没有新报告，行尾标成「可能已停」。
- **资料**：目标、步骤、事项上挂的文件、链接、命令。焦点目标内联显示，其他目标和超过 3 条的折叠成「资料 N 条」，点开再看。文件和链接行尾常驻「打开」按钮，点文件名或链接本身也能打开；终端里鼠标移上去还会在「打开」左边出现「VS Code」「复制路径」「×」，没有鼠标悬停的界面里常驻「复制」和「×」。

**待你看**：Claude 把事项交给你过目（状态 `◆`）时，看板顶部的「待你看」区块列出它：标题、所属目标 › 步骤、多久前交的，以及可点开的入口。它只是提醒加跳转，不是审批：

- 看完点 **[看过了]**，事项变成 `◇` 已看，离开「待你看」，状态仍是「待你看」。
- 某个入口不想再看到，点它旁边的 **[×]** 隐藏；隐藏的入口收进「▸ 已隐藏 N 条」，展开后点 **[恢复]** 找回。一个事项的入口全部隐藏，视同已看。
- 看过 / 隐藏只记在本机，不改 `ai/board.json`，Claude 不会知道。Claude 再次把事项交给你（重新报告，或挂了新入口）时，它会重新出现在「待你看」里。
- 验收结论直接在对话里告诉 Claude（「这个通过了」「这里要改」），由它更新事项状态。

**颜色只有两种**：绿色表示「现在有事在发生、轮到你或正在跑」（在跑、待你看、有待确认的提议），灰色表示其余一切。扫一眼看绿色的地方就够了。

**电池格进度**：每个目标旁边一排格子，一个事项一格，做完的格子点亮；最后一格要等全部做完才亮，所以不会出现「看着满了其实没完」。

**小螃蟹**（标题区，只在终端里显示）：它的姿势告诉你全局状态——有东西刚完成时欢呼；有事等你看或确认时挥手；看板可能落后于实际进度时挠头；有事项在跑时干活；其余时间睡觉。不喜欢可以在设置里关掉。

看板会在右侧画成侧边栏（横屏终端），或画在输入框上方（竖屏）。`/board` 一键收起或打开。

## Claude 怎么用它

- **自动读取**：每个会话开始时，看板里的当前关注、约定、进行中的目标与决策会被压缩后放进 Claude 的上下文（有长度上限，放不下的会注明条数，Claude 可以用 `board_get` 按需查全文）。
- **随手记录**：Claude 推进工作时用 `board_update` 更新事项状态、记录决策和约定；你在对话里拍板的事，它会带上你的原话记为决策。你在对话里给出的验收结论（通过、要改），它会在同一次更新里写进事项状态。「看板没更新」的提醒只在两种情况下出现：它派了子 agent 却没写看板，或收到子 agent 的结果后没写看板（子 agent 自己写过看板的不算）；只改文件不会触发。别处（如另一个会话）对看板的改动，只有要紧的才会在下一条消息时告诉它：目标、事项状态、步骤、决策、约定、关注和提议的变化；事项备注、资料、关联之类的小修改不通知。
- **自己拆步骤**：增删步骤不需要你确认。
- **你说了算的事**：新建、改名、合并、关闭、暂停或恢复目标，以及修改「当前关注」，只能经你同意：在看板卡片上点「同意」，或在对话里明确表示同意后由 Claude 带着你的原话执行。几个目标其实是同一件事的不同阶段时，对 Claude 说「把这几个目标合并」，它会提议合并，你点同意后每个旧目标变成一个步骤，事项、关联、决策都跟过去。
- **一次一批**：一批更新要么全部生效，要么全不生效，不会写到一半。

## 命令

| 命令 | 作用 |
|---|---|
| `/board` | 看板在屏幕上就收起（「已收起看板」），不在就按屏幕形状打开：横屏开右侧侧边栏（「已打开看板（右侧）」），竖屏或侧边栏放在输入框上方时展开输入框上方的看板（「已打开看板（输入框上方）」） |
| `/board 决策 [目标名] [页码]` | 生效中的决策，最近的在前；目标名可只写一部分 |
| `/board 约定 [页码]` | 项目约定，按分组列出 |
| `/board 资料 [页码]` | 项目资料，按分组列出 |
| `/board 归档 [关键词] [页码]` | 已关闭的目标和随之归档的决策 |
| `/board init [类型]` | 创建看板 |

列表（决策、约定、资料、归档）只显示给你，不进入 Claude 的对话；要让 Claude 改某一条，直接说它的编号（如 `d-k3m9qa`）。每页最多 40 行、3,000 字符，末尾给出下一页的命令。`claude -p` 与 SDK 这类一次性运行没有交互界面，列表照常作为命令输出打印。

## 设置项

安装时或之后在 `/config` 里设置：

| 设置项 | 取值 | 说明 |
|---|---|---|
| `layout` | `auto`（默认）/ `right` / `bottom` | `auto` 按终端形状选：横屏用右侧侧边栏，竖屏画在输入框上方；`right` 总用侧边栏；`bottom` 总画在输入框上方 |
| `motion` | `on`（默认）/ `off` | `on` 让转圈和小螃蟹动起来，事项完成、进度上涨、步骤完成时有短动效；`off` 全部静止。Claude Code 自己的「减少动效」打开时同样静止；三分钟没有任何变化或操作后，持续动效降到每秒 2 帧 |
| `mascot` | `on`（默认）/ `off` | 是否在标题区画小螃蟹，关掉后标题文字左移 |

## 会读写什么、按钮会执行什么

- **读写范围**：读写当前项目里的 `ai/board.json`（创建看板时在项目根新建它）和上面的本机视图记录文件。另外会列出 `ai/sprints/active/` 下的目录并读取其中的 `BRIEF.md`（见下文 pflow-sprint 联动），只读。插件自己不联网。
- **看板按钮**：
  - 「打开」：macOS 用系统 `open` 打开文件或文件夹、Linux 用 `xdg-open`；链接用系统默认浏览器打开。
  - 「VS Code」：macOS 上用 `open -a "Visual Studio Code"` 打开该路径；Linux 上只有本机装了 `code` 命令时才显示。
  - 「复制」：把路径、地址或命令复制到剪贴板。**命令类关联只复制、从不执行**；以 `cd <相对路径>` 开头的命令，复制出来的路径会换成项目根下的绝对路径。
  - 命令失败时退化为复制路径。
  - 同意、不要：只修改 `ai/board.json`。
  - 看过了、×、恢复：只写本机视图记录文件（见下），不改 `ai/board.json`。
- **本机视图记录**：`~/.cache/project-board/view/<hash>.json`（`<hash>` 由项目路径算出），只记你看过哪些交付、隐藏了哪些入口。不进 git，Claude Code 和 pi 共用；删掉它只会让已看 / 已隐藏的东西重新出现。
- `ai/board.json` 随项目进 git，建议提交，换电脑或同事克隆后看板自然还在。

## 和 pflow-sprint 一起用（可选）

如果你的项目用 pflow-sprint 一类的 sprint 工作流（约定：进行中的 sprint 放在 `ai/sprints/active/<名字>/`，里面有 `BRIEF.md` 和 `PLAN.md`），project-board 会自动联动；没有这个目录则完全不受影响。

- 看板是项目总览：每个进行中的 sprint 对应看板上的一个目标，目标里挂着该 sprint 的 `PLAN.md`，点开就能看计划。
- sprint 里每一步做到哪了，只记在它自己的 `PLAN.md`，看板上这个目标只记整体状态、等你过目的节点和你拍板的决策。挂着 `PLAN.md` 的目标不拆步骤、不参与合并。
- 新开 sprint、结束 sprint 时，Claude 会在看板上提议建目标、关闭目标，出现在待确认卡片里，你点同意才生效。
- 在已有 sprint 的项目里创建看板时，每个进行中的 sprint 会自动生成一条待确认的目标提议（标题取 `BRIEF.md` 的第一个标题），不同意就点「不要」。

## 在 pi 里使用

同一个项目里，Claude Code 和 [pi](https://pi.dev) 可以共用同一份 `ai/board.json`：谁改了看板，另一边会在下一条消息时被告知「外部：……」（只报要紧的变化），两边的约定、决策、目标进度不会各记各的。

安装（本地仓库路径，或把仓库当作 pi 包）：

```
pi install /path/to/claude-project-board
pi install git:github.com/a809384377/claude-project-board     # 发布后
pi -e ./pi/project-board.ts                                    # 只试用一次，不写入设置
```

在 pi 里能用的：

- **四个工具**：`board_get`、`board_update`、`board_propose`、`board_init`，与 Claude Code 里同名同参。项目里没有看板时只有 `board_init`（走 tool search，不占上下文）。
- **会话开始的看板快照**：作为系统提示的一个段落（`<project_board>`）注入，整个会话内文字不变；别处的改动和「看板没更新」的提醒（仅派了子 agent 却没写看板时），随你的下一条消息带进去。
- **`/board` 命令**：和 Claude Code 版相同（`决策` `约定` `资料` `归档` `init`），列表只显示在对话里，不发给模型；不带参数是收起 / 展开输入框上方的看板。
- **和 Claude Code 版同一块看板**：同一份界面代码（`hooks/view/board.tsx`）在 pi 里照样画——像素小螃蟹和计数药丸、「待你看」「待你确认」框、目标的竖条与电池进度条、步骤条、入口按钮、动效。横屏（全屏模式、宽 ≥ 100 列且行数 × 2 ≤ 列数）时停靠在右侧，竖屏或窄屏时画在输入框上方；`[-]` 或 `/board` 收起成一行，再点一行或 `/board` 展开。
- **用鼠标操作**：点按钮（看过了、×、恢复、同意 / 不要、打开、VS Code、复制路径、设为关注）、点目标 / 步骤 / 事项展开折叠、滚轮滚动放不下的部分。同意写入 `ai/board.json` 时记为你本人；看过了 / × / 恢复只写本机视图记录。
- 环境变量：`PI_PROJECT_BOARD_LAYOUT=auto|right|bottom`（默认 auto：按屏幕形状；right 总是右侧，bottom 总是输入框上方）、`PI_PROJECT_BOARD_WIDGET=compact`（启动时收起成一行）或 `off`（不显示）、`PI_PROJECT_BOARD_MOTION=off`（关闭动效）。颜色用终端的真彩色（`COLORTERM=truecolor`），否则降到 256 色。

和 Claude Code 版的差别：

- 右侧停靠依赖 pi 的全屏模式（默认）和它的布局内部接口；`--tui-mode regular` 或停靠失败时，看板退回输入框上方，且**不能用鼠标**：对 AI 说「同意」，它会带着你的原话调用 `board_propose` 执行；验收结论同样在对话里说（「这个通过了」），由它更新事项。
- 输入框上方的看板最多占约 45% 屏高（常规模式为屏高减 12 行），放不下的部分靠滚轮（仅全屏模式）。
- pi 的子 agent（`PI_SUBAGENT_CHILD=1` 的进程）只能提议，不能代你同意，也不注入快照、不显示看板。
- 「看板落后」的检查把 pi 的 `subagent` 工具算作派了 agent。

两个宿主同时写同一个文件时，写入前会再读一次文件：发现别处刚改过就在新内容上重做（最多 4 次），不会盖掉对方的改动；极短的窗口（两个进程在几毫秒内同时提交）仍可能丢一次更新。

开发：改了 `hooks/view/board.tsx` 之后运行 `bun pi/scripts/gen-board.ts` 重新生成 `pi/gen/board.js`（pi 的加载器不支持 JSX；`bun test pi/tests` 里有检查生成物是否过期）。`bun test pi/tests`（pi 适配层，与 `claude plugin test .` 互不干扰：pi 的测试文件叫 `*.spec.ts`）。

## 兼容性

- 需要 Claude Code **2.1.287 或更新**（插件系统中的 mod 支持），在 **2.1.296** 上测试通过。
- 动效颜色取自 Claude Code 内部的主题色表；Claude Code 大版本更新后，这些颜色可能需要跟着调整，表现为颜色略有偏差，不影响功能。
- VS Code 聊天面板和 `claude -p` 里不显示看板；看板工具和注入照常可用。

## 升级注意

写入了步骤的看板文件会标为 `schema: 2`。旧版本（没有步骤功能的版本）读到 schema 2 只会报「未知版本」、不会写入。按这个顺序升级：

1. 更新插件。
2. 关掉或重启所有有看板项目的旧会话（它们还在用旧代码）。
3. 在重启后的会话里才开始用步骤或合并。

某个会话里看到「未知版本：schema 2」，说明它没有重启：重启该会话即可。**不要用 git 把 `ai/board.json` 恢复成旧版本。** 没用到步骤的看板继续写 schema 1，旧会话不受影响。

`ai/board.json` 的格式没有变化，更新插件不需要重启其他会话。尚未更新的会话仍显示旧的验收按钮，两个版本可以并存。

## 更新插件

自建市场默认不自动更新，需要时手动执行：

```
claude plugin update project-board@claude-project-board
```

更新后重启会话。

## 开发

在仓库根目录：

```zsh
claude plugin validate .            # 校验市场文件、插件清单和 hooks 模块（--strict 把警告也当错误）
claude plugin test .                # 跑全部测试（在 Claude Code 自带的测试引擎里）
npx -y -p typescript@5.6.3 tsc -p tsconfig.json   # 类型检查，应无输出
```

类型检查依赖 Claude Code 自动生成的类型声明目录 `.claude-plugin/types/`（已被 `.gitignore` 忽略，体积大，不随仓库分发）。生成方式：在这个目录里用 `claude --plugin-dir .` 开一个交互会话，Claude Code 加载插件时会把它写到 `.claude-plugin/types/`；之后即可运行上面的 `tsc`。

本地试用改动：`claude --plugin-dir .`，改了源码后在会话里 `/reload-plugins`。

目录结构：`pi/` 是 pi 的适配层（`project-board.ts` 为入口，复用 `hooks/` 里与宿主无关的部分；`ui/` 是画 Claude 版同一棵界面树的小渲染器和停靠 / 滚动 / 点击，`gen/` 是 board.tsx 的生成物），`hooks/` 是插件代码（`register.ts` 为入口；`model/` 是看板数据与规则，`view/` 是界面，`store.ts` 管读写，`tools.ts` 注册 Claude 用的工具），`tests/` 是测试，`types/` 是插件自己的状态类型声明。

## 数据结构

文件 `ai/board.json`，2 空格缩进、键顺序固定，随项目进 git。`id` 由 mod 生成：前缀加 6 位随机 base36（`g-k3m9qa`），在活动区和归档区内不重复。

### 顶层

| 字段 | 说明 |
|---|---|
| `schema` | `1` 或 `2`。活动区和归档区都没有步骤、也没有待确认的 `goal.merge` 提议时写 `1`（不含 `steps` / `stepId` 字段），否则写 `2`；两种都能读。比这更新的版本拒绝写入，提示更新插件或重启会话 |
| `rev` | 每次写入加 1，用于展示与同步 |
| `project` | `name` 项目名；`type` 可选，项目类型（如 `miniapp`），供 skill 识别 |
| `focus` | 当前关注：`text`、`goalId`（可空）、`mandate`（授权范围，可空）、`updatedAt` |
| `milestones` | `enabled` 是否启用；`items` 为里程碑列表 |
| `goals` | 进行中和暂停的目标 |
| `decisions` | 决策日志 |
| `rules` | 约定 |
| `notes` | 项目资料 |
| `proposals` | 待用户确认的提议 |
| `archive` | `goals`、`decisions`：已关闭的目标及随之归档的决策 |

### 目标 Goal

| 字段 | 说明 |
|---|---|
| `id` `title` `outcome` | 编号、标题、做到什么算完（一句话） |
| `status` | `active` / `paused` |
| `links` | 关联列表（Link） |
| `steps` | 步骤列表（Step），顺序即步骤条顺序；没有步骤为 `[]`（schema 1 中省略）。步骤状态不存，由事项推出 |
| `items` | 事项列表（Item） |
| `confirmedBy` `quote` | 新建时的确认方式（`conversation` / `sidebar`）和用户原话 |
| `createdAt` `updatedAt` | ISO 8601 时间 |
| `closedAt` `closeReason` | 仅归档区：关闭时间、`完成` / `放弃` |

### 步骤 Step

目标内的阶段（如 A→B→C→D），由 Claude 自行增删，不需要用户确认。`id` 前缀 `s`，全局唯一。

| 字段 | 说明 |
|---|---|
| `id` `title` | 编号、标题 |
| `label` | 步骤条上的短名；空则由标题推出（标题开头的编号，否则第一个 `：:、` 或空格前的部分，否则前 4 个字） |
| `note` | 说明；`goal.merge` 时放旧目标的成果与用户原话 |
| `links` | 这一步的资料，形状同 Link |

### 事项 Item

| 字段 | 说明 |
|---|---|
| `id` `title` | 编号、标题 |
| `stepId` | 所属步骤，空字符串表示不属于任何步骤；必须是同一目标下的步骤（schema 1 中省略） |
| `status` | `todo` 待办 · `queued` 排队 · `doing` 在做 · `running` 在跑 · `review` 待你看 · `done` 完成 · `dropped` 搁置 |
| `owner` | 负责方，主会话写 `main`，可空 |
| `note` | 备注 |
| `waitingFor` | `queued` 时写在等什么 |
| `dependsOn` | 排在哪些事项之后（事项 id 列表，须在活动区存在） |
| `scope` | 该事项持有、别人不该同时改的文件或目录 |
| `acceptance` | 做到什么算完 / 怎么验 |
| `links` | 关联列表，含「待你看」的入口 |

| `forReview` | `true` 表示「待你看」里的入口 |
| `step` | 可选，数字：同一事项多个入口的先后顺序（与看板步骤无关） |

### 写入规则

- 事项进入 `review` 时应挂上 `forReview` 关联（让你能从看板打开）；没有时 `board_update` 照常写入，并在结果里提示 Claude 补上。已有入口的事项又挂了不同的入口时，同样提示它移除不再需要的旧入口。`noReviewTargetReason` 可选，说明没有可看的东西的原因。
- 目标的新建、改标题或成果、合并、关闭、暂停 / 恢复，以及当前关注的修改，只能经用户确认后执行：在看板卡片上点「同意」，或用户在对话里明确同意后由 Claude 带原话执行。
- 关闭目标时，目标、步骤、事项和指向它的决策一起移入 `archive`；当前关注指向它则清空；引用它的待确认提议（`payload.goalId` 或 `payload.goalIds` 含它）一并删除；别的事项对被移走事项的依赖自动解除。
- `goal.merge {title, goalIds, outcome?}` 把 2 个以上活动区目标合并成一个新目标：每个没有步骤的旧目标成为一个步骤（成果与用户原话进步骤说明，关联跟着进步骤，事项挂到步骤上）；已有步骤的旧目标，步骤原样搬入，成果与原话追加到它第一个步骤的说明，关联按 `target` 去重并入新目标。指向旧目标的决策和关注改指新目标，引用旧目标的其他提议删除，旧目标不进归档；暂停的旧目标合并后一并恢复。
- 一批操作要么全部生效，要么全不生效；文件无法解析、`schema` 未知或读不出来时拒绝写入，不覆盖原文件。
- 文件超过 2 MiB 时标题栏提示「归档已很大」。

## 没有 mod 的环境

未安装 mod、`--safe-mode` 或不支持 mod 的环境里，Claude 看不到看板工具，只能读 `ai/board.json`。在项目的 CLAUDE.md 里加一句即可：

> 项目状态在 `ai/board.json`，由 project-board mod 维护；没有 mod 时只读，需要改动时请用户在装有 mod 的会话里操作。

## 已知限制

- 两个会话在同一瞬间（读与写之间的几毫秒）写同一个看板，后写的会覆盖先写的那一次改动，事后无法发现。一个主会话加它的子 agent 在同一进程内串行写入，不受影响。
- VS Code 聊天面板和 `claude -p` 里不显示看板；看板工具和注入照常可用。
- 只拉高窗口不会切换横竖屏：横竖屏按终端宽度变化时重新判断（屏幕旋转会改变宽度）；需要固定时用 `layout` 设置。
- 打开按钮依赖本机命令：macOS 用 `open`，Linux 用 `xdg-open`，Linux 上只有本机有 `code` 命令时才显示 VS Code 按钮（macOS 总是显示）；命令失败时退化为复制路径。
