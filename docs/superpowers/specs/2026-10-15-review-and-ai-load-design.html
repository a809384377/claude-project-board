目标

  1. 看板上等用户过目的事项只负责「提醒 + 跳转」，结论由用户在对话里给出，AI 据此更新看板。
  2. 用户能自己清理看板上的过时入口，且清理动作不产生任何发给 AI 的信息。
  3. 看板一屏内的信息量减到「一眼能扫完」。
  4. AI 只接收会改变它下一步做法的信息；看板不主动触发 AI 运行，也不制造只为「告知」的上下文。
判别标准：一条要交给 AI 的文字，如果 AI 读后不会改变任何行为，就不交。

一、待你看（用户侧，本机状态）

行为

  • 顶部区块标题为「待你看」，列出所有 status = review 且未被用户收起的事项。每行：状态图标、标题（单行截断）、所在目标 › 步骤、交上来的时间（取 reportedAt，显示为「2 小时前」）、按钮 [看过了]。行下列出该事项的验收入口（forReview 关联）。
  • [看过了]：该事项从「待你看」区块消失；在所属目标里仍按 review 显示，但图标变为 ◇、文字变暗、行尾标「已看」。事项状态不变。
  • 重新出现：用户收起的是「这一版」。事项的 reportedAt 变化（AI 再次把它设为 review），或其 forReview 入口集合变化（AI 挂了新文件），该事项重新进入「待你看」。
  • [×]：每条关联（目标、步骤、事项上的都算）行尾一个 [×]，点后该关联在本机隐藏。一个事项的验收入口全部被隐藏时，视同 [看过了]。
  • 找回：被隐藏的关联在其所属目标 / 步骤 / 事项下折叠为一行「▸ 已隐藏 N 条」，展开后每条带 [恢复]。
  • 移除全部「验收通过」按钮和对应的盖章动效；approveItem 动作删除。事项只由 AI 根据对话改为 done。
  • 顶部计数药丸「◆ 待你」只计未收起的 review 事项；吉祥物的「等你」姿势同样只看未收起的事项与待确认提议。

本机状态的存放

  • 文件：~/.cache/project-board/view/<项目根绝对路径的 sha1 前 16 位>.json，Claude Code 与 pi 共用同一份。
  • 内容：
{
  "seen":   { "<itemId>": "<reportedAt>|<排序后的 forReview target 以 \n 连接的 sha1 前 12 位>" },
  "hidden": { "<ownerId>": ["<link target>", "..."] }
}
  • seen 的值等于事项当前指纹时视为已看；不等即重新出现。ownerId 为目标 / 步骤 / 事项 id。
  • 不写入 ai/board.json，不进 git，不产生 store 变更事件，因此不进入 AI 的「外部变化」通知。
  • 读写失败（无权限、文件损坏）时按空状态处理并 toast 一次，不影响看板其他功能。
  • 指向已不存在的事项 / 关联的条目不主动清理：它们不影响显示，体积可忽略。

「待你确认」提议卡片

保持现有「同意 / 不要」按钮（会真实执行）。卡片底部加一行暗色提示「也可以在对话里直接说」。

示意：文件名即「打开」，其余按钮悬停时出现；空步骤只留在步骤条里。

  • 事项一行：标题 truncate-end 截成一行；行尾短标签依次为 @owner、等：<waitingFor 截 12 字>。备注、依赖、验收标准、入口全部收进点开后的详情。
  • 其他会话的在跑事项：行尾标「别的会话 · 07-10 21:30」；reportedAt 距今超过 12 小时改为「可能已停」。纯显示逻辑，不通知 AI。
  • 空步骤：没有事项的步骤只在步骤条里出现，下方不渲染步骤标题行，即使用户曾展开过它。
  • 关联行：文件名本身是「打开」按钮；VS Code、复制路径、[×] 放在行尾：
    • 终端画布（支持 hover）：鼠标悬停该行时才显示，沿用目标行「设为关注」的 hover 写法。
    • 不支持 hover 的界面（pi、文本降级）：常驻显示 [复制] [×]，不显示 VS Code。
  • 目标资料：默认折叠为「▸ 资料 N 条」（阈值从 3 降为 0，即一律折叠），焦点目标除外。

三、AI 侧减负

规则文本

  • 工作规则只保留一份：留在 board_update 的工具说明里；会话快照（RULES_TEXT）只保留一句定位说明（「以下是会话开始时的看板快照；之后的变化随用户消息告知，最新内容用 board_get」）。
  • 删除「你自己替用户做的非关键判断记 kind=delegated」。decision.add 的 kind 仍接受 delegated，以兼容旧数据和旧会话。
  • 新增两句（并入现有规则，不另起条目）：
    • 事项标题不超过约 25 字，过程细节写进 note。
    • 用户在对话里给出验收结论后，在同一次 board_update 里更新该事项状态（done，或回到 doing / 拆出修改事项）并移除不再需要的入口。
  • 第 3 条改为：「事项进入 review（待用户过目）时挂上验收入口（forReview 关联），让用户能从看板直接打开。」去掉「必须」与 noReviewTargetReason 的要求。

校验从拦截改为提示

  • checkInvariants 删除「review 必须有入口」这一条；noReviewTargetReason 字段保留读写，仅不再强制。
  • board_update 成功结果的 events 里追加提示类事件（kind: 'hint'），只在以下情况出现：
    • 事项变为 review 但没有 forReview 入口：「事项「X」没有验收入口，用户无法从看板打开它」。
    • 给已有 forReview 入口的事项再加 forReview 入口：「事项「X」已有入口：A、B；不再需要的用 item.link.remove 移除」。
  • 提示只出现在 AI 本来就在做的这次调用的返回里，不额外触发调用。

外部变化通知（随用户下一条消息附带）

describeChanges 只保留会影响 AI 判断的变化：

保留去掉
关注变更；目标新增 / 关闭 / 合并 / 暂停 / 恢复 / 改名 / 移除目标成果改写、目标关联增减
事项新增 / 删除 / 状态变化 / 换目标事项改名、换步骤、负责人、备注、等待事项、验收标准、关联增减
步骤新增 / 删除步骤改名、短名、说明、关联增减、换目标
决策新增 / 被替代 / 恢复决策文字修改
约定新增 / 删除约定修改；资料（notes）的一切变化；里程碑的一切变化
提议出现 / 被处理—

去掉的变化 AI 需要时可用 board_get 查到。

「看板没更新」提醒

  • 触发条件改为：本轮主会话调用过派子 agent 的工具（Claude Code Agent，pi subagent）且本轮没有写看板。只改文件不再触发。
  • 提醒文字：「上一轮派了 N 个 agent，看板未更新；如有进展请补记」。
  • 标题区「⚠ 看板可能落后」与吉祥物挠头沿用同一个标记，随之收窄。
待实现时确认：宿主能否识别「由子 agent 完成通知触发的回合」。能识别则该回合同样适用上面的条件（处理了 agent 结果却没写看板）；不能识别则只按派出判断。

/board 列表命令

/board 决策 / 约定 / 资料 / 归档 的输出面向用户，目标是只显示、不进入对话上下文。

待实现时确认：
  • pi：sendMessage 的显示型消息是否会进入模型上下文；可选方案是改用通知或 widget 显示。
  • Claude Code：命令输出是否有不进上下文的选项。
能做到则改为只显示；做不到则保持现状，并在 README 说明输出会进入对话。

数据与兼容

  • ai/board.json 格式不变，schema 不升级，新旧版本插件可同时读写。
  • 旧版本插件仍会显示「验收通过」按钮并能把 review 事项写成 done，与新版本不冲突。
  • 本机视图文件是新增文件，旧版本不读取。

测试

  • 本机视图状态：指纹匹配 / 不匹配；reportedAt 变化与入口集合变化后重新出现；全部入口隐藏视同已看；文件损坏按空状态处理。
  • 视图：已看事项不进待你看、计数不含已看、隐藏关联不显示且出现「已隐藏 N 条」、恢复后重新显示、空步骤不渲染标题行、无 hover 界面的按钮集合。
  • 模型：review 无入口可写入并产生 hint；重复挂 forReview 入口产生 hint；describeChanges 只输出保留类别。
  • 同步：只改文件不产生提醒；派 agent 未写看板产生提醒；派 agent 且写了看板不提醒。
  • pi：bun test pi/tests 通过，生成物不过期。
  • 真机：在 Claude Code 与 pi 会话里各手动走一遍：AI 交一个待你看 → 看过了 → AI 再挂新入口后重新出现 → [×] 隐藏 → 恢复。

不做

  • 不把「看过了」「隐藏」同步给 AI 或写进项目看板文件。
  • 不给关联新增时间字段；时间取事项的 reportedAt。
  • 不新增 AI 在会话开始时核对在跑事项的流程。
